Quatre familles de particules (rouge, bleue, verte, blanche, de masses différentes) s'attirent ou se repoussent selon une table de coefficients issue d'un objet de réglage unique (positif : répulsion, négatif : attraction, d'après le calcul), avec une force en 1/distance². La simulation démarre quand on lance un préréglage depuis la galerie (voir CAP-SIMULATION-CHOISIR-UNE-SIMULATION-DANS-UN), positions initiales aléatoires ; une seule simulation tourne à la fois. Les types, couleurs, nombres et règles viennent du préréglage choisi (de même forme que l'objet de `settings.js`) ; ils peuvent ensuite être modifiés en direct depuis le panneau de réglages.

Ce mode est celui par défaut (`interaction: "rules"`) ; un préréglage peut le remplacer par la gravitation universelle entre corps massifs (`interaction: "gravity"`, sans matrice de règles ni portée : voir CAP-APPLIQUER-LA-GRAVITATION-UNIVERSELLE-ENT). Les règles ci-dessous sont celles du mode par défaut.

Règles : deux particules plus éloignées que la portée d'interaction n'exercent aucune force l'une sur l'autre ; la distance est majorée d'une constante epsilon (10 dans les préréglages, réglable dans le panneau) pour éviter les divisions par zéro ; une gravité verticale facultative (0 par défaut, à ne pas confondre avec la gravitation universelle) ajoute une accélération constante verticale à toutes les particules ; le rayon dépend de la masse (masse / 2 + 2 pixels). La simulation avance d'un pas par image affichée, sauf si le calcul d'un pas prend plus d'une image : elle ralentit alors sans que l'affichage soit bloqué. Le calcul tourne en arrière-plan (Web Worker), en double précision.

Réglage : un objet JavaScript (`settings.js`) décrit les types (nom, couleur, nombre, masse), les règles (coefficient d'un type vers un autre ; règle absente = aucune interaction), epsilon, la friction, la gravité (`gravity`, facultative), les bords, la portée (`range`, en pixels ; illimitée si absente dans `settings.js`, obligatoire et finie dans les préréglages en mode des règles), le mode d'interaction (`interaction`, `"rules"` par défaut ou `"gravity"`, avec sa constante `G`) et le nombre de dimensions (`dimensions`, 2 par défaut ; 3 avec une profondeur `depth` : voir CAP-SIMULER-EN-TROIS-DIMENSIONS). Trois réglages sont dans `settings.js` : le réglage historique (`defaultSettings`, portée illimitée, mêmes résultats que la version précédente du moteur), le réglage de départ (`startSettings`, le même avec une portée de 60 pixels, repris par le préréglage « Quatre familles ») et une configuration de 20 000 particules (`referenceSettings` : rouge ×800, bleue ×18 900, verte ×50, blanche ×250, portée de 30 pixels) ; `defaultSettings` et `referenceSettings` ne sont pas affichés par la page, ils servent de référence aux tests. Un test automatique vérifie qu'un pas à 10 000 particules en 2D avec une portée finie tient en moins de 50 ms ; un autre, qu'un pas à 200 corps en mode gravité tient en moins de 5 ms. Le moteur fonctionne sans navigateur et est couvert par des tests ; à graine identique, le résultat est reproductible.

Les modifications faites dans le panneau ne sont pas sauvegardées : revenir à la galerie ou recharger la page remet le réglage du préréglage, dont le fichier n'est jamais modifié.

Limites : aucune interaction avec les particules (souris, clavier) ; seuls les préréglages de la galerie sont proposés (ni création, ni téléversement, ni sauvegarde de réglage) ; avec une portée illimitée ou très grande, le calcul redevient en O(n²) et lent pour des dizaines de milliers de particules ; le temps de calcul grandit avec la portée et avec le regroupement des particules. L'objectif de 60 images par seconde à 20 000 particules n'a pas encore été mesuré sur un portable de référence (sur le processeur de développement, un pas prend environ 15 ms). Les noms « électron », « eau », « noyau », « proton » ne sont que des commentaires.

Code : `settings.js`, `engine.js`, `simulation-host.js`, `simulation.worker.js`, `main.js`, `renderer.js`, `presets/`
